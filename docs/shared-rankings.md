# 공유 랭킹

`pokemon.pir.kr/api/rankings?mode=time-easy`에서 순위를 읽고, `/api/scores`에 게임 결과와 트레이너 이름을 등록합니다. 같은 사이트의 CloudFront가 이 경로만 API Gateway HTTP API / Lambda로 전달합니다. 게임 이미지와 파일은 기존 S3에서 제공합니다. API는 캐시하지 않습니다.

랭킹 화면은 타임어택 / 마스터 탭, 그 아래 쉬움 / 보통 / 어려움 버튼을 사용합니다. 모드·난이도 조합 6개는 분리되어 저장합니다. 각 조합의 TOP 20, 날짜, 금·은·동메달과 등록한 자신의 행을 표시합니다. 화면 진입과 모드·난이도 선택 시 기록을 조회합니다. 15초 동안은 받은 기록을 재사용하고, 저장할 때는 최신 순위를 다시 확인합니다.

## 데이터와 저장

DynamoDB `pokemon-play-prod-rankings`는 `mode`를 키로 하며, 각 항목에 20개 이하의 기록과 버전을 저장합니다. 기록은 id, name, mode, score, correct, total, date로 구성됩니다. 점수 내림차순으로 비교하며 동점은 최근 등록한 기록을 먼저 보여줍니다. 기존 기록도 조회할 때 같은 순서로 정렬합니다. 버전 조건을 붙여 동시에 들어온 기록이 기존 기록을 덮어쓰지 않도록 갱신합니다. 같은 제출 ID를 재시도하면 중복 등록하지 않습니다.

프론트엔드는 순위 확인 후 이름 입력창을 표시하고, 저장 성공 응답을 받은 뒤 저장 완료로 표시합니다. 저장 실패나 응답 시간 초과에는 입력한 이름을 유지하고 재시도할 수 있습니다. 전송한 정답 결과 배열과 힌트 사용 배열로 서버에서 점수를 계산합니다. 마스터에서 힌트를 쓴 문제는 정답 점수의 절반을 받으며, 기록에 hintsUsed 수를 보관합니다. 힌트 필드가 없는 기존 제출은 힌트 없음으로 처리해 이전 클라이언트와 호환합니다. 마스터는 1~10문제(그만하기 포함), 타임어택은 110문제 이하 등 게임의 범위를 확인합니다. 이 공개 익명 API는 로그인이나 서버 주도 문제 출제를 사용하지 않으므로 제출된 정답 결과가 실제 사람의 플레이인지를 증명하는 기능은 포함하지 않습니다.

기존 `pokemon-play-records` 개인 기록은 삭제하지 않고, 다른 사람에게 자동으로 공개하지 않습니다. 공유 기능 이후 새로 저장한 기록부터 다른 기기에 보입니다. 자신의 공유 기록 ID만 `pokemon-play-last-shared-id`에 저장해 강조 표시합니다.

## AWS와 비용

DynamoDB on-demand, Python 3.13 ARM64 Lambda(256MB, 8초, 동시 실행 5개), HTTP API를 사용합니다. API에는 초당 10개 / 순간 20개 요청 제한을 두고, Lambda 로그는 7일만 보존합니다. 상시 서버, RDS, VPC, NAT, 웹소켓, 정기 폴링을 추가하지 않습니다. 테이블은 스택 삭제 시 보존합니다.

AWS의 [DynamoDB 요금 안내](https://aws.amazon.com/dynamodb/pricing/)와 [HTTP API 안내](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api.html)를 참고했습니다. 요청·저장량과 계정의 무료 범위에 따라 실제 비용이 결정됩니다.

Lambda 역할에는 이 테이블의 GetItem / PutItem만 부여합니다. 사이트 배포 역할은 기존 정적 파일 배포 권한에 이 Lambda의 UpdateFunctionCode / GetFunctionConfiguration만 추가합니다. 테이블 삭제나 조회 전체 Scan 권한은 주지 않습니다.

## 배포 순서

처음에는 기존 `PokemonPlayProd` 스택에 API / Lambda / DynamoDB / CloudFront API 경로를 배포해야 합니다. `aws sso login --profile podbbangcast` 로그인 후 `npm run aws:diff -- --profile podbbangcast`로 검토하고 `npm run aws:deploy -- --profile podbbangcast`로 적용합니다. API가 준비된 뒤 공유 랭킹 프론트엔드를 `main`에 반영합니다.

CI에서 게임·동시 등록·저장 재시도·기기 간 공유와 배포 권한을 검사한 다음 웹 릴리스와 별도 Lambda ZIP을 만듭니다. 두 artifact의 revision과 체크섬이 일치해야 배포합니다. 검증된 Lambda 코드를 먼저 갱신하고 완료를 기다린 뒤 HTML을 마지막으로 교체합니다. 서버 소스는 공개 S3 릴리스에 넣지 않습니다.

`npm run ci`는 AWS 자격 증명 없이 소스·테스트·릴리스·CloudFormation 생성까지 검사합니다. 실제 DB 연결은 AWS 배포와 두 브라우저의 저장·조회 검사로 추가 확인합니다.

첫 방문에서 입력한 트레이너 이름은 브라우저에 기억하고 랭킹 입력에 자동 채웁니다. 저장 전에 해당 기록의 이름을 수정할 수 있습니다. 그만하기는 종료 랭킹을 열고 얻은 점수를 등록하며, 다시 도전은 선택한 모드·난이도의 시작 화면으로 돌아갑니다. 날짜는 한국 달력 기준 상대 시각으로 표시합니다.

마스터의 시간 보너스는 이미지가 준비된 뒤 20초 안에 맞힌 경우 최대 기본 점수의 50%를 더합니다. 클라이언트는 문제별 `elapsedMs` 정수(0~20000)를 전달하며 서버는 힌트를 쓴 문제·오답에는 보너스를 더하지 않습니다. `timeBonus` 합계를 저장하고 재시도의 메타데이터도 비교합니다. 시간이 없는 이전 클라이언트와 기록은 보너스 0으로 호환됩니다. 시간 값은 익명 클라이언트가 측정하며 서버 주도 출제·시간 검증은 포함하지 않습니다.


## 메모리게임

화면에는 타임어택과 메모리게임 탭을 표시합니다. 마스터 도전은 메인과 랭킹에서 숨기며 기존 게임 코드와 기록은 보존합니다. 8/12/15쌍의 완료 시간으로 memory-easy/memory-normal/memory-hard의 TOP 20을 별도로 비교하며, 이름별 가장 짧은 완료 시간을 남깁니다. 순위 계산은 durationMs 오름차순이고 동점에는 최근 날짜를 우선합니다. 새 기록에는 durationMs, moves, pairs와 기존 이름/파트너/기기 정보를 보관합니다. 미완료 도전에는 등록하지 않으며 기존 점수 보드는 변경하지 않습니다. 원본 이력과 idempotent 저장은 기존과 동일하게 적용합니다. 화면은 초 단위 소수점 둘째 자리까지 표시하지만 순위는 원본 밀리초로 비교합니다.

카드 수 조정 후 이전 6/8/10쌍 및 어려움 16쌍의 기록은 원본으로 보존하고 새 카드 수의 랭킹에서는 제외합니다. 조회만으로 이전 행을 변경하지 않으며 다음 보드 갱신 전에 기존 원본을 이력에 보존합니다.


## 월간 랭킹

새 화면은 한국 시간(Asia/Seoul) 기준 이번 달의 랭킹을 기본으로 표시합니다. 이전/다음 달 버튼으로 이동하며 모드·난이도를 유지합니다. 별도 이번달 복귀 버튼은 제공하지 않습니다. 월 선택은 목록 패널에 이어지는 헤더로 표시하고 현재 달 제목은 이번달, 과거 달은 9월처럼 표시합니다. 난이도를 바꾸면 이번 달로 돌아갑니다. 순위 목록은 해당 달을 사용하고 개인 최고기록은 전체 기간을 비교합니다. 오늘 기록은 HH:mm, 1~6일 전은 N일전, 7일 전부터는 10월29일 형식으로 표시합니다.

월별 보드는 같은 테이블의 month#YYYY-MM#<모드> 항목에 독립적으로 보관합니다. 이름별 최고점/최단 시간 TOP 20 및 최근 동점 우선 규칙은 같습니다. 기존 전체 보드와 history 원본은 유지합니다. 새 클라이언트는 GET /api/rankings?mode=...&month=YYYY-MM 및 POST /api/scores?month=YYYY-MM을 사용합니다. month 없는 이전 클라이언트의 응답은 전체 보드 형식을 유지하되 신규 저장은 월별 보드에도 반영합니다. 저장할 달은 서버가 발급한 원본의 한국 시간 날짜로 결정하며 클라이언트가 지난달을 임의 선택할 수 없습니다. 월간 갱신 실패 후 재시도에서도 원래 날짜·달·ID를 유지합니다.

일반 조회는 GetItem만 사용하고 DB에 쓰지 않습니다. 기존 전체 보드에서 같은 달의 행도 읽어 월별 보드와 병합합니다. 과거 전체 TOP 20에서 밀려난 보존 이력까지 월별로 복구하려면 배포 전 scripts/backfill-monthly-rankings.py를 SSO 계정으로 실행합니다. 기본은 읽기 전용 dry-run이고 --apply일 때만 기존 전체/이력 원본을 보존하면서 월별 항목을 조건부 병합합니다. 운영 백업을 먼저 확보하고 동시 저장과 충돌하면 재조회합니다. 이 과정은 기존 전체 보드·초대·기기·설정을 삭제하거나 덮어쓰지 않습니다. 과거에 이미 삭제되고 보존 이력에도 없는 기록은 복구할 수 없습니다. 이전 메모리 카드 수의 원본은 보존하며 현재 카드 수와 섞지 않습니다.

Lambda의 기존 GetItem/PutItem 권한만 사용하고 테이블/인덱스/IAM 변경은 없습니다. 전체 원본 Scan은 배포 준비용 SSO 도구에서만 실행합니다. 운영 반영 시 검증된 서버 코드를 웹보다 먼저 배포합니다.


## 점수 결과와 개인 최고기록

유효한 게임 기록은 종료 후 해당 게임을 시작한 트레이너 이름·파트너 정보로 자동 등록합니다. 이름 입력 버튼은 제공하지 않습니다. 첫 기록 또는 개인 최고기록 경신 때만 저장 성공 뒤 읽기 전용 순위 레이어를 열고, 동점·미달이면 점수/완료 시간 화면을 유지합니다. TOP 20 밖의 신기록도 원본 및 개인 최고기록으로 저장하고 정확한 순위를 추측하지 않고 TOP 20 밖으로 구분해 표시합니다. 0점·이미지 오류·미완료 메모리게임은 등록하지 않습니다. 저장 실패는 결과 화면에 재시도를 제공하며 같은 기록 ID를 재사용합니다. 저장 중 중복 요청은 하나로 합치고 다른 화면으로 이동한 뒤 도착한 응답은 자동 레이어를 열지 않습니다. 개인 최고기록은 월간 순위와 별도로 같은 트레이너·모드·난이도의 전체 기간 기록과 비교합니다. 경신/미달/동점/첫 기록/미완료의 다섯 상황별 문구를 세 개씩 순환하며 화면 재렌더링에는 문구를 유지합니다. 미달이면 최고 점수 또는 최단 시간을 함께 표시합니다. 이 기기에서 완료한 기록도 로컬에 보관해 등록하지 않은 도전의 최고기록을 기억합니다.

서버의 personal#<모드>#[카드수#]<이름해시> 항목은 저장된 전체 기간 개인 최고기록을 보존하므로 TOP 20 밖으로 밀려난 뒤에도 비교할 수 있습니다. GET 월간 랭킹에 trainer 파라미터를 주면 personalBest를 반환하며 기기 ID와 User-Agent는 공개 응답에서 제외합니다. 기존 GetItem/PutItem 권한으로 조건부 갱신하며 초대/기기/설정은 수정하지 않습니다. 기존 원본의 월별 복구 도구는 이 개인 최고기록도 생성/병합합니다. 전체/월간/원본 이력은 그대로 보존하고 이전 메모리 카드 수의 개인 기록도 별도 키로 유지합니다.


게임 상단 제목은 이름맞추기에서 이 포켓몬, 누구일까?, 메모리게임에서 같은 포켓몬을 찾아봐!로 표시하며 카드 안의 중복 제목은 제공하지 않습니다. 메모리게임 시작 화면은 난이도 → 카드 앞면/뒷면 미리보기 → 시작 버튼 순서로 표시하며 난이도의 쌍 수 표시는 생략합니다. 실제 쉬움 8쌍·보통 12쌍·어려움 15쌍과 저장 검증은 유지합니다. 배포 내역과 데이터 보존 확인은 운영 문서에 기록합니다.
